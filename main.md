Neo4j × HackFront India Mini-Hack: Problem Statements & Judging Framework Date: 26 September 2026 Venue: DataPhi, Pune Format: Workshop + 2-Hour Build Sprint + Team Demonstrations Participants: Students + Working Professionals Team Size: 2–4 participants 1. Mini-Hack Theme Build an AI Agent That Remembers Participants will build an AI-powered prototype using Neo4j as a meaningful part of the memory and relationship layer. The objective is to demonstrate how persistent memory and connected information can make AI agents more contextual, personalized and useful. Participants can choose one of two problem statements: 1. 2. Context-Aware Customer Support Agent Personal Productivity & Decision Memory Agent Both challenges will use the same judging framework. 2. Build Sprint Scope The build sprint will be limited to approximately 2 hours. Participants are therefore expected to build a focused functional prototype, rather than a productionready system. Participants should focus on: • • • • • • One clearly defined user journey One meaningful memory workflow A functional AI agent Meaningful Neo4j integration Demonstrable memory retrieval A clear before/after demonstration 1Participants are NOT expected to build: • • • • • • Production-grade authentication Complete enterprise workflows Large-scale datasets Complex front-end applications Fully autonomous multi-agent systems Production-level security/scalability The quality of the core Agent Memory + Neo4j implementation will be more important than the number of features. 3. Common Technical Requirements Regardless of the problem statement selected, every team should demonstrate: 1. AI Agent An AI-powered agent capable of interacting with a user and/or performing a defined task. 2. Persistent Memory The agent should retain relevant information beyond a single interaction. 3. Neo4j Integration Neo4j should meaningfully represent, store, connect and/or retrieve relevant information. 4. Contextual Retrieval The agent should retrieve relevant information from previously stored memory or connected entities. 5. Memory-Driven Improvement The team should demonstrate that the agent provides a more contextual, personalized or useful response because of its memory. 4. Problem Statement 1 Context-Aware Customer Support Agent Challenge Build an AI-powered Customer Support Agent that remembers previous customer interactions and uses relationships between the customer, product, issue and previous resolution to provide more contextual support. 2The goal is to demonstrate how persistent memory can reduce repetitive conversations and improve the quality of customer support. Example Scenario A customer contacts support: Customer: "My course access isn't working. I purchased the course last week and already contacted support about this." The agent should capture the relevant information. Later, the customer returns: Customer: "It's still not working." Instead of treating this as a completely new conversation, the agent should retrieve the relevant history and respond based on the previous interaction. For example, it could identify: Customer → Product → Previous Issue → Previous Support Interaction → Resolution/Status and use this context in its response. Expected Prototype Within the 2-hour build sprint, teams should focus on one support journey. A possible flow: Step 1 — Customer Interaction Customer reports an issue. ↓ Step 2 — Memory Creation Relevant customer, product and issue information is stored in Neo4j. ↓ Step 3 — New Interaction The customer returns with a follow-up question. 3↓ Step 4 — Memory Retrieval The agent retrieves relevant previous interactions and relationships. ↓ Step 5 — Contextual Response The agent responds using the retrieved information. Suggested Data Model Teams may use a simple graph such as: Customer → Order → Product Customer → Support Ticket → Issue Support Ticket → Resolution Customer → Previous Interaction Participants may extend this model where useful. Possible Extensions Teams with additional time may explore: • • • • • • • Similar historical support issues Customer preferences Product-specific issue patterns Previous resolutions Escalation recommendations Support-agent handoff Identifying unresolved issues These are optional and should not be required for judging. 45. Problem Statement 2 Personal Productivity & Decision Memory Agent Challenge Build an AI-powered Personal Productivity & Decision Memory Agent that remembers a user's preferences, tasks, decisions, commitments and previous outcomes. The agent should use this accumulated context to provide more personalized recommendations and assist the user in making or revisiting decisions. Example Scenario During an initial interaction, a user tells the agent: "I prefer meetings in the morning and usually need two days to prepare for important client presentations." The user also makes a decision: "I'll prepare the presentation on Monday because the client meeting is on Wednesday." The agent stores this information. Later, the user asks: "Help me plan my week." The agent should use the user's previous preferences, commitments and decisions to create a more relevant plan. Expected Prototype Within the 2-hour build sprint, teams should focus on one productivity/decision workflow. A possible flow: Step 1 — User Interaction User provides preferences, tasks or makes a decision. ↓ 5Step 2 — Memory Creation Relevant information is stored in Neo4j. ↓ Step 3 — New Interaction User asks for a recommendation, schedule or decision support. ↓ Step 4 — Memory Retrieval The agent retrieves relevant preferences, tasks, decisions or outcomes. ↓ Step 5 — Personalized Recommendation The agent provides a recommendation using the retrieved context. Suggested Data Model Teams may use a simple graph such as: User → Preference User → Task User → Decision → Reason Decision → Outcome User → Commitment/Event Participants may extend the model where useful. Possible Extensions Teams with additional time may explore: • • • • Decision history Decision → outcome tracking Learning from previous outcomes Conflicting preferences 6• • • • Priority-based planning Recurring tasks Personalized recommendations "Why did I make this decision?" queries These are optional. 6. Success Criteria for the Mini-Hack The challenge is successful if participants can demonstrate, within the available build time: A working AI agent + persistent memory + meaningful Neo4j graph usage + contextual retrieval + a clear improvement in the agent's response. The event should prioritize depth of one working use case over breadth of features. A simple, reliable prototype that clearly demonstrates Agent Memory and Neo4j should be considered stronger than a larger but incomplete application.
